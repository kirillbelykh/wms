# Интеграция WMS с локальным агентом Честного Знака

## Цель

Перенести полноценный операторский интерфейс `kontur_api` в WMS как новый раздел `Честный знак`, не ломая текущую схему, где `kontur_api` и WMS работают отдельно.

## Что уже закрепляем

1. В WMS остаются два разных раздела:
   - `ЧЗ` — для склада и производства, чтобы отправлять запросы на коды и смотреть историю.
   - `Честный знак` — для менеджеров и операторов, с полным функционалом `kontur_api`.
2. `kontur_api` продолжает существовать как отдельная desktop-утилита.
3. Новый режим в WMS работает поверх локального web-агента, который запускается на том же ПК, где запущен `kontur_api`.

## Базовая схема

### 1. Локальный агент на каждом ПК

При запуске `kontur_api` на ПК поднимается локальный HTTP-сервер:

- по умолчанию на `127.0.0.1:8787`
- опционально HTTPS на `127.0.0.1:8788`
- сервер слушает только loopback, а не внешний интерфейс

Он отдает:

- embed-версию интерфейса `ui_v2`
- API-вызовы к локальному `ApiBridge`
- health-check для WMS

### 2. Новый раздел `Честный знак` в WMS

WMS не делает прямые вызовы в ЧЗ/Контур/BarTender. Вместо этого:

1. пользователь открывает раздел `Честный знак` в WMS
2. frontend WMS проверяет локальный агент на `localhost`
3. если агент доступен и привязан к текущему пользователю, WMS встраивает нужный экран `kontur_api` в embed-режиме

### 3. Привязка к пользователю

На каждом ПК в `.env` локальной утилиты указывается:

- `WMS_BOUND_USER=<username>`

Это нужно, чтобы WMS понимала, что локальный агент на этом ПК предназначен для конкретного пользователя.

Пример:

```env
WMS_BOUND_USER=ivanov
WMS_ALLOWED_ORIGINS=https://wms.grund-lage.ru,http://localhost:5173,http://127.0.0.1:5173
WMS_EMBED_SERVER_ENABLED=1
WMS_EMBED_SERVER_HOST=127.0.0.1
WMS_EMBED_SERVER_PORT=8787
WMS_EMBED_SERVER_HTTPS_ENABLED=0
WMS_EMBED_SERVER_HTTPS_PORT=8788
```

## Потоки работы

### Оператор/менеджер

1. Заходит в WMS.
2. Открывает раздел `Честный знак`.
3. WMS подключается только к локальному агенту на его ПК.
4. Любые действия:
   - заказ кодов
   - загрузка кодов
   - ввод в оборот
   - ТСД
   - агрегация
   - печать
   выполняются локально на этом ПК через `kontur_api`.

Это гарантирует:

- если печать запускает Аня, печать идет на ПК Ани
- если заказ кодов делает Ваня, запрос выполняется через утилиту Вани

### Склад/производство

Существующий WMS-раздел `ЧЗ` остается отдельным слоем:

1. кладовщик или бригадир делает запрос ЧЗ в WMS
2. запрос уходит в очередь/интеграцию
3. оператор открывает раздел `Честный знак` и берет заявку в работу
4. после `Коды готовы` WMS получает обратный статус и уведомления

## Безопасность

1. Встроенный агент по умолчанию слушает `127.0.0.1`, а не `0.0.0.0`.
2. CORS ограничен `WMS_ALLOWED_ORIGINS`.
3. Прямая связь идет только между браузером пользователя и локальным агентом на его ПК.
4. Внешний VPS не открывает входящие соединения к операторским ПК.
5. Существующий `CHZ_BRIDGE_TOKEN` остается для текущих WMS-интеграций и обратной совместимости.

## Обратимость

Если потребуется быстро откатиться:

1. в WMS можно скрыть раздел `Честный знак`
2. пользователи продолжают запускать `kontur_api` отдельно, как сейчас
3. раздел `ЧЗ` в WMS продолжает работать по текущей логике

То есть новая схема не заменяет старую одномоментно, а наслаивается поверх нее.

## Что реализуем поэтапно

### Этап 1

- embed-режим `kontur_api`
- новый раздел `Честный знак` в WMS
- проверка локального агента
- привязка к пользователю через `.env`

### Этап 2

- перенос критичных операторских сценариев в React/WMS по одному экрану
- унификация дизайна под WMS без iframe-зависимости

### Этап 3

- полный отказ от отдельного UI при необходимости
- `kontur_api` остается только как локальный агент, печать, CryptoPro, cookies и сетевой исполнитель

## Ограничения на текущем этапе

1. Для каждого рабочего ПК нужен локально запущенный `kontur_api`.
2. На новом ПК надо прописать `WMS_BOUND_USER` и при необходимости `WMS_ALLOWED_ORIGINS`.
3. Полный React-перенос всех экранов `kontur_api` в WMS — это отдельный этап, а не мгновенная замена.
